# 1단계. 회원·가구 관리와 마이페이지 설계

## 구현 순서

1. **회원·가구 관리와 마이페이지 (이 문서)**
2. [신혼부부 맞춤 주택 공고](2026-11-22-personalized-housing-notices-design.md)
3. [우리 집에 맞는 혜택](2026-11-22-personalized-household-benefits-design.md)

로그인, 공통 가구 프로필, 마이페이지의 회원 관리와 탈퇴를 먼저 구현한다. 관심 공고 관리 영역은 2단계의 저장 기능과 연결하며, 그때 관심 공고도 탈퇴 시 삭제 범위에 포함해 검증한다.

## 목표와 범위

신혼부부와 예비부부가 네이버 또는 카카오로 가입·로그인하고, 마이페이지에서 내 정보와 가구 조건을 수정하고 관심 공고를 다시 볼 수 있다. 로그아웃과 회원 탈퇴도 마이페이지에서 시작한다.

- 첫 버전은 한 계정에 한 가구 프로필을 둔다. 배우자 초대·공동 편집, 여러 로그인 수단 연결·변경, 알림 설정은 후속 범위다.
- [맞춤 주택 공고](2026-11-22-personalized-housing-notices-design.md)와 [우리 집에 맞는 혜택](2026-11-22-personalized-household-benefits-design.md)이 같은 계정과 가구 프로필을 사용한다. 관심 공고의 저장·갱신 규칙은 주택 공고 설계에서 정의한다.

## 검토한 접근과 결정

| 접근                        | 장점                                                                       | 비용과 제약                                                          |
| --------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 마이페이지 한 곳에서 관리   | 내 정보, 가구 조건, 관심 공고, 로그인 계정과 탈퇴를 한 곳에서 찾을 수 있다 | 자주 쓰는 가구 정보와 계정 변경 작업을 화면에서 분명히 구분해야 한다 |
| 마이페이지와 계정 설정 분리 | 계정 설정이 늘어날 때 각 화면의 역할이 분명해진다                          | 첫 버전에서도 여러 화면을 오가야 한다                                |

첫 번째 접근을 채택한다. 마이페이지에서 모든 관리 항목에 접근하고, 탈퇴는 삭제 범위 안내와 본인 확인을 거치는 별도 흐름으로 연결한다.

## 가입·로그인과 마이페이지

- 첫 소셜 로그인에 성공하면 서비스 계정을 생성한다. 이후에는 동일한 공급자 계정으로 돌아올 수 있다. 이메일이 같다는 이유로 네이버와 카카오 계정을 자동으로 합치지 않는다. 재시도해도 같은 공급자 사용자의 계정이 중복 생성되지 않아야 한다.
- 로그인은 기존 Supabase 환경을 활용한다. 공급자별 연결 방식, 가입 완료에 필요한 설정과 콜백, 세션 검증 방법은 구현 계획에서 확인한다. 인증이 완료되면 원래 보던 서비스 내부 화면으로 돌아간다. 취소나 실패 시 다시 시도할 수 있다.
- 마이페이지는 로그인한 본인에게만 제공한다. 공개 공고·혜택 탐색은 계속 이용할 수 있다. 가구 조건 입력 전에도 계정 관리와 관심 공고 저장을 이용할 수 있다.
- **내 정보**에서는 서비스에서 표시할 이름을 선택 입력하고 변경할 수 있다. 로그인에 연결된 공급자는 확인용으로 표시한다. 공급자에서 관리하는 정보는 해당 공급자에서 변경한다.
- **가구 조건**에서는 저장한 값을 조회·수정하고, 선택 입력 항목을 지울 수 있다. 변경 내용은 다음 공고·혜택 조회에 반영한다. 저장에 실패하면 편집 중인 값을 유지하고 재시도할 수 있게 한다.
- **관심 공고**에서는 저장 목록의 공고와 최신 상태를 보고 상세로 이동하거나 저장을 해제할 수 있다.
- **로그아웃**은 현재 로그인 세션을 종료하고 공개 화면으로 돌아간다. 다음 로그인 때 저장한 정보를 다시 볼 수 있다.

## 공통 가구 프로필

| 입력                                       | 처리 원칙                                                                                                                                    |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 희망 지역                                  | 시·도 전체와 여러 시·군·구를 함께 선택할 수 있다. 현재 거주지와 별도로 저장한다.                                                             |
| 신청자와 배우자의 소득                     | 월평균 소득을 원 단위로 각각 입력한다. 0원과 미입력을 구분하며, 혜택이 연소득 등 다른 산정 기준을 요구할 때는 필요한 정보를 추가로 확인한다. |
| 주택 소유 여부                             | 신청자·배우자 각각 소유·미소유·모름을 기록한다. 세대 범위나 과거 보유 이력이 필요한 경우 해당 공고·혜택에서 확인한다.                        |
| 혼인 상태·혼인신고일, 가구원 수, 자녀 정보 | 자격이나 순위 계산에 필요한 범위로 입력받는다. 날짜와 자녀 범주의 해석은 공고·혜택의 기준일과 정의를 따른다.                                 |
| 실제 거주지와 연속 거주 시작일             | 신청자와 배우자의 지역을 각각 입력할 수 있다. 실제 주소의 상세 번지 대신 평가에 필요한 행정구역과 거주 시점을 사용한다.                      |
| 청약 납입 인정 회차, 자산 등               | 검토한 규칙이 요구하는 경우 목적을 안내하고 필요한 항목만 입력받는다. 입력을 건너뛴 경우 필요한 판정은 확인 필요로 남긴다.                   |

- 계정당 가구 프로필을 저장하고 데이터베이스와 서버에서 본인의 접근만 허용한다. 공개 카탈로그, URL, 로그, 분석 이벤트, 사용자 간 공유 캐시에 개인별 조건이나 판정 결과를 넣지 않는다. 증빙 서류 업로드는 범위에서 제외한다.
- 첫 버전의 공통 저장 항목은 희망 지역, 두 사람의 월평균 소득·주택 소유 여부·현재 거주 행정구역과 연속 거주 시작일, 혼인 상태·혼인신고일, 가구원 수다. 예비부부도 두 번째 사람의 조건을 입력할 수 있으며 혼인 여부는 별도로 판단한다. 연령, 자녀 세부 정보, 청약 회차, 자산 등은 필요한 판정에서 추가로 받아 해당 계산에만 사용한다.
- 마이페이지는 저장된 사실을 편집한다. 특정 공고 기준일의 과거 조건이나 이사 가정은 해당 기능의 평가 문서에 따라 처리한다.

## 회원 탈퇴

1. 삭제될 서비스 계정, 가구 프로필, 관심 공고와 복구 불가 여부를 안내한다. 네이버·카카오 자체 계정은 계속 이용할 수 있음을 표시한다.
2. 연결된 공급자로 본인을 다시 확인하고 탈퇴를 확정한다. 확인하는 계정이 현재 서비스 계정과 일치해야 한다. 재인증을 취소하거나 실패하면 계정과 저장 정보는 그대로 유지된다.
3. 탈퇴가 시작되면 개인화 데이터 접근과 수정을 차단한다. 서비스 계정과 소유 데이터를 삭제하고 모든 서비스 세션의 접근을 종료한다. 이미 발급된 인증 정보로 개인화 기능을 다시 사용할 수 없어야 한다.
4. 확정된 탈퇴 요청은 브라우저를 닫아도 계속 처리한다. 작업이 중단되면 정리 작업을 안전하게 재시도한다. 아직 정리 중인 동일 공급자 계정이 다시 들어오면 새 계정 생성을 보류하고 처리 중임을 안내한다. 삭제에 성공하면 완료 화면에서 공개 탐색으로 이동할 수 있다. 삭제 완료 후 다시 가입할 경우 이전 프로필과 관심 공고는 복원되지 않는다.

## 구현 계획에 넘길 항목

- 네이버·카카오 공급자 설정, 취소·실패 처리, 서비스 내부 복귀 경로, 공급자별 재인증 방식과 두 공급자 계정의 자동 연결 방지 방법을 확인한다.
- 가구 프로필, 회원 정보, 관심 공고에 대한 소유권 정책과 삭제 범위를 확정한다. 삭제 작업의 순서, 중복 요청, 중단 후 복구, 동시에 들어오는 쓰기와 기존 세션의 재접근 차단을 검증한다.
- 기존 FSD 레이어 규칙에 따라 계정 기능과 공통 가구 프로필을 구성한다. 마이페이지 경로와 각 관리 항목의 화면 구성은 구현 계획에서 정한다.

## 완료 기준

- 네이버·카카오 각각에서 첫 가입, 재로그인, 취소·실패 후 재시도, 내부 화면 복귀를 확인한다. 동일 이메일의 다른 공급자 계정에 상대 계정의 데이터가 노출되지 않는다.
- 로그인하지 않은 사용자는 마이페이지에 접근할 수 없고, 다른 계정의 가구 정보와 관심 공고를 읽거나 바꿀 수 없다. 표시 이름과 가구 정보를 수정하고 선택 항목을 지울 수 있으며, 맞춤 공고와 혜택 모두에 최신 조건이 반영된다.
- 로그아웃 후 다시 로그인하면 프로필과 관심 공고를 다시 볼 수 있다. 탈퇴 취소, 다른 공급자 계정으로 재인증, 두 브라우저의 기존 세션, 브라우저를 닫거나 삭제가 중단된 경우의 재처리, 탈퇴 완료 후 재가입을 검증한다.
- `/benefits`, `/benefits/raw`, `/housing`의 공개 탐색과 마이페이지·로그인 진입 흐름을 직접 확인한다.
