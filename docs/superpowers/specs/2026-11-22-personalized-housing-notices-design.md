# 2단계. 신혼부부 맞춤 주택 공고 설계

## 구현 순서

1. [회원·가구 관리와 마이페이지](2026-11-22-account-and-household-management-design.md)
2. **신혼부부 맞춤 주택 공고 (이 문서)**
3. [우리 집에 맞는 혜택](2026-11-22-personalized-household-benefits-design.md)

1단계의 로그인과 공통 가구 프로필을 활용한다. 주택 공고 탐색과 개인별 판정, 관심 공고 저장을 구현하고, 저장 목록을 마이페이지에 연결한다.

## 목표와 범위

신혼부부가 네이버 또는 카카오로 로그인하고 가구 조건과 희망 지역을 저장하면, 신청을 검토할 만한 공공임대·공공분양 공고를 찾을 수 있다. 공고별로 확인된 자격 조건, 추가 확인이 필요한 정보, 계산 가능한 예상 순위·배점을 원문 근거와 함께 제공한다.

- 마이홈의 공공임대·공공분양 목록을 희망 지역으로 탐색할 수 있다. 조건을 저장한 사용자는 같은 목록에서 개인화 결과를 확인한다.
- 로그인한 사용자는 관심 있는 임대·공공분양 공고를 저장하고 다시 볼 수 있다.
- 첫 판정 기준은 경기북부 신혼·신생아 매입임대Ⅰ과 안산신길2 A-6블록 신혼희망타운 공공분양을 대상으로 검증한다. 두 공고의 접수 기간은 각각 적용하며, 접수 종료 후에는 직접 접근 가능한 상세 및 검증 사례로 활용한다.
- 이번 버전은 마이홈 공고와 신혼부부 신청 경로에 집중한다. 민영분양, 신청 대행, 경쟁자 대비 순위·당첨 확률, LLM 파싱 실험은 후속 범위다.
- 로그인·공통 가구 프로필·마이페이지는 [회원·가구 관리 설계](2026-11-22-account-and-household-management-design.md)를 따른다. 맞춤 혜택 홈과 공고 상세의 주거비 지원은 [우리 집에 맞는 혜택 설계](2026-11-22-personalized-household-benefits-design.md)에서 다룬다.
- 사용자 입력이나 공고에 근거가 부족해도 탐색을 이어갈 수 있어야 한다. 누락값이나 해석하지 못한 예외를 자동으로 통과 또는 0점 처리하면 사용자가 신청 기회를 놓칠 수 있다.

## 검토한 접근과 결정

| 접근                                                            | 장점                                                                      | 비용과 제약                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 지역 탐색을 폭넓게 제공하고, 검토된 공고에 단계적으로 판정 추가 | 임대·공공분양 모두 탐색 가능하며 초기 판정의 범위를 명확히 표시할 수 있다 | 공고별 판정 지원 여부와 누락된 조건을 설명해야 한다                        |
| 검토를 마친 공고만 맞춤 탐색에 노출                             | 모든 노출 공고의 판정 기준을 설명할 수 있다                               | 초기 공고 범위가 각 유형의 소수 사례로 좁아진다                            |
| 전 공고의 PDF를 LLM으로 정규화한 뒤 맞춤 기능 제공              | 문서 형식이 다양한 공고의 구조화 범위를 늘릴 수 있다                      | 호출비, 정정공고 재처리, 각주·예외 검수에 드는 시간이 아직 측정되지 않았다 |

첫 번째 접근을 채택한다. 기존 수집·파싱을 활용하고 사람이 원문과 대조한 규칙만 사용자 판정에 사용한다. LLM 정규화를 검토할 때는 검토까지 마친 공고당 비용과 오류 유형을 작은 표본에서 측정할 수 있다.

## 사용자 흐름

1. `/housing`에서 비로그인 상태로 임대·공공분양 목록과 상세 공고를 둘러본다. 로그인 진입점은 가구 조건을 저장하고 맞춤 결과를 이용할 때 제공한다.
2. 네이버 또는 카카오 로그인 후 가구 조건을 입력한다. 로그인 완료 후 원래 보던 목록이나 상세로 돌아갈 수 있다. 로그인 취소나 실패 시 재시도할 수 있다.
3. 희망 지역은 시·도 전체와 여러 시·군·구를 함께 고를 수 있다. 예를 들어 서울 전체와 경기 고양·파주를 하나의 설정으로 저장한다. 공고에 지역이 여러 곳이면 선택한 지역과 겹치는 공급 지역을 표시한다. 희망 시·군·구의 시·도까지만 알려진 경우에는 목록에 남기고 `세부 지역 확인 필요`를 표시한다.
4. 기본 결과에는 희망 지역의 접수 중·예정 공고를 보여준다. 검토된 공고는 사용자에게 열려 있거나 확인이 필요한 신청 경로의 일정으로 표시하고, 전체 일정만 알려진 공고에는 공고 단위 일정임을 표시한다. 정렬은 접수 상태와 일정을 기준으로 한다. 접수 종료 공고와 자격 미충족 공고는 별도로 다시 볼 수 있게 한다. 판정에 필요한 정보가 부족한 공고는 목록에 남긴다.
5. 공고 상세에서 확인된 조건과 원문, 추가로 입력할 항목, 해당되는 예상 순위·배점을 확인한다. 프로필 변경 후에는 최신 조건으로 다시 계산한다.

## 관심 공고 저장

- 목록과 상세에서 공고를 저장하거나 해제할 수 있다. 공고 저장에는 로그인만 필요하며 가구 조건 입력은 선택이다. 로그인하지 않은 사용자가 저장을 선택하면 로그인 후 원래 보던 공고로 돌아와 저장을 이어갈 수 있다.
- 마이페이지의 관심 공고에서 공고 제목, 공급 유형, 지역, 최신 접수 상태를 확인하고 상세로 이동할 수 있다. 계산 가능한 개인화 결과는 현재 프로필과 공고 버전을 기준으로 보여준다.
- 사용자와 공고 ID의 조합으로 중복 저장을 방지하고, 본인만 저장 목록을 조회·변경할 수 있다. 정정공고는 기존 공고와의 연결이 확인되면 저장을 유지한다. 접수 종료·취소된 공고도 사용자가 해제할 때까지 상태를 표시하며 남긴다. 카탈로그에서 사라진 경우 확인 가능한 마지막 공고 정보와 현재 상태를 확인할 수 없다는 표시를 제공한다.
- 알림, 계정 간 공유, 공고 비교는 후속 범위다.

## 공고 수집과 판정 규칙

- 현재 카탈로그의 공고 ID, 지역, 공급 유형, 접수 기간과 PDF 상태를 사용한다. 자동 추출 표는 어떤 기준을 검토해야 하는지 찾는 데 활용한다.
- 검토된 규칙에는 공고 ID, 원문 PDF URL·버전 식별자, 판정 기준일, 공급 지역 또는 공급 단계, 적용 조건·예외, 근거 쪽수를 기록한다. 소득표에는 가구원 수, 소득 산정 범위, 맞벌이 여부, 금액 비교 기준을 포함한다.
- 공고문과 각주를 대조해 자격, 순위·공급 단계, 배점 규칙을 승인한다. 규칙 내용과 근거는 함께 검토 가능한 형태로 관리한다. 원문이 정정되거나 검토 당시 버전과 다르면 기존 판정을 보류하고 다시 검토한다. 취소 공고는 맞춤 결과에서 안내 대상에서 제외한다.
- 판정은 개인별 요청에서 구조화된 규칙과 프로필을 대조해 계산한다. 목록 상태는 희망 지역과 겹치는 공급 지역의 신혼부부 신청 경로를 기준으로 합친다. 해당 경로가 하나라도 충족하면 그 경로를 표시한다. 미충족으로 표시하고 기본 목록에서 접으려면 해당 경로가 모두 검토됐고 각각 불충족이어야 한다. 지역이 불명확하거나 미검토 경로가 남아 있으면 확인 필요로 목록에 남긴다. 검토 규칙이 없는 공고는 지역 탐색 결과로 제공한다.
- 가구 조건은 공고의 자격 기준일로 평가한다. 현재 프로필로 기준일 당시 조건을 확인할 수 없으면 해당 공고에서 기준일을 보여주고 추가 확인을 받는다. 첫 버전에서는 이 답변을 그 공고의 계산에만 사용하며 가구 이력으로 저장하지 않는다. 같은 공고 안에서 공급 지역이나 단계마다 기준이 다르면 각각 평가한다. 소득 상한과 배점 구간의 경계값, 각주에 따른 보정 및 중복 적용 여부를 원문대로 반영한다.
- 접수 종료 후에도 공고 요약과 원문은 열람할 수 있다. 종료된 공고에는 현재 신청을 위한 개인별 결과 표시를 종료하며, 검토한 버전은 내부 검증 사례로 유지한다.

## 결과 표시

| 상태               | 사용자에게 보여주는 내용                                            |
| ------------------ | ------------------------------------------------------------------- |
| 입력한 조건 충족   | 충족한 신청 경로와 확인한 조건, 기준일과 원문 쪽수                  |
| 입력한 조건 미충족 | 해당하는 경로의 차단 조건, 입력값과 공고 기준                       |
| 추가 확인 필요     | 빠진 입력, 확인이 필요한 예외, 검토 중인 원문 버전 등 구체적인 사유 |
| 자격 판정 준비 중  | 규칙이 아직 없어 지역과 접수 정보로 탐색할 수 있는 공고             |

- 매입임대는 계산 가능한 예상 입주 순위와 동순위 배점을 표시한다. 공공분양은 신청 가능한 공급 단계와 단계별 배점 또는 추첨 여부를 표시한다. 서로 다른 공고나 공급 단계의 점수를 합산해 정렬하지 않는다.
- 배점은 확인한 항목과 미확인 항목을 함께 보여준다. 필요한 항목이 모두 확인된 경우에만 총점을 표시한다. 순위에 영향을 주는 상위 조건이 미확인이라면 예상 순위도 보류한다.
- 모든 판정과 점수는 사용자 입력을 기준으로 계산한 예상 결과로 표시하며, 공급기관의 공고 원문과 접수 안내로 바로 이동할 수 있어야 한다.

## 구현 계획에 넘길 항목

- 지역 코드와 공고 지역의 매핑, 기존 `/housing` 흐름에 맞춘 입력과 결과 화면, 공고의 접수 상태 표시.
- 관심 공고 식별자와 저장·해제 흐름, 사용자별 접근 제어, 카탈로그 갱신 및 공고 누락 시 표시.
- 검토 규칙의 저장 형태와 공고 버전 연결, 검토·게시 과정, 자격 및 배점 평가기의 책임 분리. 기존 FSD 레이어 규칙을 따른다.
- 두 사례의 공식 PDF를 대조해 필요한 추가 입력, 적용 경로, 예외와 경계값을 확정한다. 화면에 쓰는 기존 상세 요약을 검토의 출발점으로 사용한다.

## 완료 기준

- 공고 목록과 상세의 저장 상태가 일치하고, 가구 조건 미입력 상태에서도 저장과 해제가 가능하며, 재로그인 후 저장 목록을 유지한다. 중복 요청, 다른 계정의 접근, 정정·종료·취소 또는 카탈로그에서 사라진 공고의 표시를 검증한다.
- 지역 복수 선택과 시·도 전체 선택, 여러 지역을 포함하는 공고, 시·도 수준만 알려진 공고를 검증한다. 희망 지역 밖의 충족 경로가 맞춤 결과를 바꾸지 않고, 희망 지역 안에 미검토 경로가 있으면 공고가 계속 노출된다. 희망 지역을 바꿔도 현재 거주 조건은 그대로 적용된다.
- 임대 예시에서 예상 입주 순위와 동순위 점수를, 공공분양 예시에서 공급 단계별 배점과 추첨 표시를 원문과 일치하는 사례로 검증한다. 소득 상한과 거주 기간의 경계값, 소득 0원과 미입력, 확인되지 않은 상위 순위, 미검토 공고, 정정·취소 및 접수 종료를 포함한다. 사전청약 당첨자와 신규 신청자의 접수 기간이 다를 때 해당 신청 경로의 일정이 표시되는지 확인한다.
- 로그인 전 목록·상세 열람과 기존 탐색이 동작하고, 맞춤 기능 변경 후 `/benefits`, `/benefits/raw`, `/housing`의 화면 동작을 직접 확인한다.
